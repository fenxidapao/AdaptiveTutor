# C 阶段多人对照实验设计（EXPERIMENT.md）

> 状态：v1.0（2026-08-23，**先写文档再拉人**——单人对照失败的教训）
> 配套：`scripts/analyze_experiment.py`（每日分析）；运行日志 `docs/EXPERIMENT_LOG.md`（含参与者标识，不随仓库分发）

## 1. 预注册假设（先写死，跑完不许改）

- **主假设**：费曼组（feynman）后测提升显著高于讲解组（lecture），α=0.05。
- **次要指标**：平均提升 pp、完成率（闭环完成人数/注册人数）、提示使用率。
- **分析红线**：不编造、不删改数据；剔除/特殊处理必须如实报告。

## 2. 参与者与分组

- **对象**：不熟 Python 的同学（前测 40-60% 才有提升空间）。
- **目标 n≥20，分两批**：第一批 10 人验证流程（数据链路/mode 分组/bug），跑通后第二批补到 20。
- **分组机制**：注册时后端自动分配（`_auto_group`：分到当前人数少的组，均衡分配），
  用户不可自选、不可改（`users.group_name` 由服务端写入）。
- **知情同意**（注册页展示）：随机分组说明（可能分到讲解组）；数据仅用于学习效果研究；
  答题数据匿名化分析；可随时退出（退出后数据不参与分析）。

## 3. 流程（每人一个闭环）

注册 → 前测（pretest）→ 诊断 → 教学环节（feynman 组：费曼先答后讲；lecture 组：直接标准讲解）
→ 练习 → 后测（posttest，不同题同难度）→ 报告。

- **mode 由服务端强制**（按 group_name），前端不可篡改（app.js 已移除 mode 传参，后端强制）。
- 教学环节差异：feynman 组走 `/api/feynman/*`（追问找盲点）；lecture 组直接看 `/api/explain` 标准讲解。

## 4. 排除标准（报告剔除与否两个版本）

| 情形 | 处理 |
|---|---|
| 前测 ≥ 90% | 标记"天花板"，主分析剔除，另附含剔除版本的对比（用户本人 ch2 前测 100% 的教训） |
| 注册后未做前测 | 不计入任何分析（纯流失） |
| 前测完成但未做后测 | 计为流失，主分析不含，报告流失率 |

## 5. 作弊 / 数据质量检测

- **答题耗时**：`assessments.elapsed_seconds`（前端计时，提交时带上）。
  标记规则：整套耗时 < 15s 或 < 每题 3s 平均 → 标记 `疑似快速作答`，主分析剔除（含剔除版对比）。
- **设备/IP 重复**：同 IP 注册多个账号 → 手动核查（日志查 `llm_logs.user_id` 分布）。
- **hint 使用率**：练习答错次数 / 答对次数，过高（>5 次未过）标记 `练习卡点`，不影响前后测数据但报告教学表现。

## 6. 分析计划（scripts/analyze_experiment.py）

1. 读 users/assessments/exercise_logs/llm_logs；
2. 每用户 pretest 与 posttest **各取第一条**（按 chapter='all'，同章对比）——回流重测不计入组间对照，
   否则会把"回流后重学再测"的高分算进来，污染对照（E1 回流 bug 的根因，务必用第一条）；
3. 提升 pp = post - pre；分组汇总：均值/中位数/样本数；
4. 组间对比（feynman vs lecture 提升均值差）；
5. 流失率、作弊标记、天花板标记；
6. 输出 markdown 报告（含剔除版与含剔除版两套数字）。

## 7. 数据管理

- 每完成一人备份：`cp data/state.db data/state.db.bak_<日期>`（Docker 部署下 exec 进容器做）。
- 实验结束后导出完整数据集（users/assessments/exercise_logs）留档。

## 8. 已知限制（报告如实写）

- n≥20 仍是小样本，p 值仅供参考，不做过强因果结论；
- 同学为便利样本（非随机抽样），存在选择偏差；
- 前后测题目难度经人工设计保证对等，但无 IRT 校准。
