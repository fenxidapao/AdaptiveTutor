# 操作系统：进程、线程与 CPU 调度

## 1. 进程与线程

- **进程**是资源分配的基本单位，也是可独立运行的基本单位；**线程**是 CPU 调度的基本单位，是进程内的一个执行流。
- 一个进程可包含多个线程。同一进程的线程**共享**进程的地址空间（代码段、数据段、堆、打开的文件描述符），但各自拥有独立的**栈、程序计数器和寄存器集合**。
- 线程切换开销小于进程切换：进程切换需要切换地址空间（刷新页表 / TLB），线程切换只切换寄存器与栈，不切换地址空间，因此更轻量。

## 2. 进程状态

- 三态模型：就绪（Ready）、运行（Running）、阻塞 / 等待（Blocked）。五态模型在此外增加新建（New）和终止（Terminated）。
- 就绪 → 运行由调度程序（dispatcher）完成；运行 → 阻塞因等待 I/O 或资源而主动让出；阻塞 → 就绪在等待的事件发生后由中断唤醒。

## 3. CPU 调度算法

- **先来先服务（FCFS）**：非抢占式，按到达顺序服务。实现简单，但"护航效应"明显——一个长作业会拖住后面所有短作业，平均等待时间长。
- **短作业优先（SJF）**：优先调度预计运行时间最短者，平均等待时间最短；但需预知运行时间（难），且可能饿死长作业。
- **时间片轮转（RR）**：抢占式，每个进程分配一个时间片，用完即让出 CPU 给下一就绪进程。时间片过小则切换开销占比过大；过大则退化为 FCFS。
- **优先级调度**：按优先级调度，可分抢占与非抢占；可能出现"优先级反转"，需用优先级继承协议缓解。
- **多级反馈队列（MLFQ）**：设置多个优先级递减的就绪队列，新进程进入最高优先级队列；用完时间片未结束则降级。兼顾响应时间与吞吐量。

## 4. 死锁

- **四个必要条件**：互斥、占有并等待（hold and wait）、不可抢占、循环等待。四个同时成立才会出现死锁。
- **预防死锁**：破坏任一必要条件。例如一次性分配所有资源破坏"占有并等待"；对资源按序申请破坏"循环等待"。
- **避免死锁**：以**银行家算法（Banker's Algorithm）**为代表，在每次分配前检查系统是否仍处于"安全状态"（存在某种推进顺序使所有进程都能完成）。
- **检测与恢复**：用资源分配图检测环路；恢复可终止进程或抢占资源。
- **鸵鸟策略**：某些系统因处理死锁代价过高而选择忽略（如个别桌面系统）。
