# 计算机网络：TCP 与 HTTP

## 1. 分层模型

- **OSI 七层**（自底向上）：物理层、数据链路层、网络层、传输层、会话层、表示层、应用层。
- **TCP/IP 四层**：网络接口层、网际层（IP）、传输层（TCP / UDP）、应用层。
- **封装与解封装**：发送时数据自顶向下每层加首部；接收时自底向上逐层去掉首部。

## 2. TCP 三次握手（建立连接）

- 第一次：客户端发送 **SYN**，序号 seq=x，进入 SYN_SENT。
- 第二次：服务端回 **SYN + ACK**，seq=y，确认 ack=x+1，进入 SYN_RCVD。
- 第三次：客户端发 **ACK**，ack=y+1，进入 ESTABLISHED；服务端收到后也进入 ESTABLISHED。
- **为什么是三次而不是两次**：防止"已失效的连接请求报文"突然又传到服务端，导致服务端误建连接、空耗资源。三次握手的第三次让服务端确认客户端确实收到了自己的 SYN+ACK。

## 3. TCP 四次挥手（释放连接）

- 第一次：客户端发 **FIN**，进入 FIN_WAIT_1。
- 第二次：服务端回 **ACK**，进入 CLOSE_WAIT；客户端进 FIN_WAIT_2。
- 第三次：服务端发 **FIN**，进入 LAST_ACK。
- 第四次：客户端回 **ACK**，进入 TIME_WAIT，等待 **2MSL** 后关闭；服务端收到即关闭。
- **为什么需要 TIME_WAIT 且等待 2MSL**：其一，确保最后一个 ACK 能到达服务端；其二，让本连接的旧报文段在网络中消失，避免影响随后建立的新连接。

## 4. TCP 可靠传输

- **序号与确认**：对每个字节编号，接收方采用累计确认。
- **超时重传（RTO）**：未收到确认即重传；RTO 基于测量的 RTT 动态计算。
- **滑动窗口**：用于流量控制，接收方通告窗口大小，发送方在窗口内可连续发送多个报文段。
- **拥塞控制**：慢启动（cwnd 指数增长）、拥塞避免（cwnd 线性增长）、快重传、快恢复；ssthresh 为慢启动阈值，区分两个阶段。

## 5. HTTP 与 HTTPS

- **HTTP** 是无状态的应用层协议，默认端口 80；报文由请求行 / 状态行、首部、空行、实体组成。
- **HTTPS = HTTP + TLS/SSL**，默认端口 443，对传输内容加密，并可对通信双方身份进行认证。
- 常用方法：GET（获取资源）、POST（提交数据）、PUT（替换资源）、DELETE（删除资源）。状态码：2xx 成功、3xx 重定向、4xx 客户端错误、5xx 服务端错误。
- **Cookie 与 Session** 用于维持状态：Cookie 保存在客户端，Session 保存在服务端。
